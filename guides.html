nf-core / sarek

Running the Sarek pipeline

Sarek requires Nextflow and a container tool like Docker, Podman, or Singularity. Use version pinning to ensure reproducibility across runs. 

nextflow run nf-core/sarek -r 3.4.0 \
  -profile docker \
  --input samplesheet.csv \
  --outdir ./results \
  --genome GATK.GRCh38 \
  --tools mutect2,vep

gatk bp

Broad Institute GATK best practices

The gold standard benchmark workflow. The pipeline structure changes between GATK minor versions, so verify command parameters with Broad's latest guide. 

# Step 1: Base Quality Score Recalibration (BQSR)
gatk BaseRecalibrator \
  -I input.bam \
  -R reference.fasta \
  --known-sites dbsnp.vcf \
  -O recal_data.table

# Step 2: Apply quality adjustments
gatk ApplyBQSR \
  -I input.bam \
  -R reference.fasta \
  --bqsr-recal-file recal_data.table \
  -O adjusted_reads.bam

operational tips

Best practices for pipeline execution

  • Version Pinning: Never launch standard pipelines using latest. Explicitly pin tool and container digest versions to ensure audit reproducibility.
  • Dry Runs: Run Nextflow workflows using -profile test on a minimal test dataset before staging large cohort runs.
  • Log Archiving: Store MultiQC reports, Nextflow execution logs (.nextflow.log), and pipeline trace files alongside the final VCF outputs.
  • Reference Panels: Ensure the reference genome build matches downstream annotation files exactly (e.g. GRCh38 vs. hg38 chromosome name formatting issues).
